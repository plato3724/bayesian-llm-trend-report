Agent 不是工具调用，是学会一个小世界
如果你正在把 Agent 学成“提示词 + 工具调用 + 工作流外壳”，这个路子有点窄。
OpenClaw 这次让人看见的，不只是又火了一个工具。它更像一个信号：Agent 已经开始碰到文件、软件、权限和流程。未来会用 Agent 的人，不一定是提示词高手，而是能把自己的小世界说清楚的人。
OpenClaw Moment 最容易被误读成一次产品爆火。
一个工具突然出圈，大家开始讨论代码 Agent、电脑使用型 Agent、权限开放、软件自动化。好像这又是 AI 圈里一个新的热词，过两个月会被下一个热词替换掉。
但如果只把它看成工具新闻，可能会错过更大的变化。OpenClaw 让一件事变得可见：**Agent（智能体）**不再只是聊天窗口里的回答者，它开始进入真实任务的现场，也碰到一个工作世界里那些过去只有人类专家才知道的例外。
这个判断来自《张小珺Jùn｜商业访谈录》EP139。张小珺这一期请到的嘉宾是苏煜，俄亥俄州立大学计算机科学与工程系助理教授、NeoCognition 联合创始人兼 CEO，研究方向是语言智能体（Language Agent），也是 2025 年斯隆研究奖（Sloan Research Fellowship）得主。
斯隆研究奖不是终身成就奖，它更像是学术界很早给出的一个判断：这个年轻研究者值得下注。这个奖 1955 年开始设立，面向美国和加拿大高校的早期研究者；2025 年这一届有 126 位入选者，每年有超过 1000 名研究者被提名。
它的分量也体现在后来的谱系里：截至 2025 年，已有 58 位斯隆研究奖得主后来获得诺贝尔奖，17 位获得菲尔兹奖。陶哲轩（Terence Tao）后来拿了菲尔兹奖，约翰·霍普菲尔德（John Hopfield）后来拿了诺贝尔物理学奖，而且他的霍普菲尔德网络（Hopfield network）本身就是神经网络历史里绕不开的一环。
把这个背景放进来，苏煜就不是在热闹外面点评 Agent 的旁观者。他长期研究语言智能体，现在又站到创业现场。所以他谈 OpenClaw 的时候，说的不是“这个工具有多强”。他更关心的是：当 Agent 开始碰到真实任务，软件就不只是工具，而会越来越像劳动交付。
焦虑也从这里开始。
如果软件开始交付劳动，知识工作当然会被重新定价。问题不只是“我会不会用 Agent”，而是“我的工作世界里，哪些东西会被 Agent 学走，哪些东西还需要我来定义、判断和校正”。
这也是这篇文章想讨论的事。会用 Agent 的人，不一定是提示词高手，而是能把自己的小世界说清楚的人。

很多人学 Agent，第一反应是学提示词、学工具调用、学工作流编排。这些东西都不是错，问题是它们只能解决一小段。
但它会把人带到一个很窄的地方：好像只要命令写得更漂亮，Agent 就会突然稳定下来；好像只要工具接得更多，Agent 就能从“能演示”变成“能托付”。
问题是，很多时候它不会。
这里要先精确定义一下靶子。本文反驳的不是“提示词没用”，也不是“工具调用没用”。它反驳的是这样一种理解：
Agent = 提示词 + 工具调用 + 工作流外壳。
也就是把 Agent 理解成一个更聪明的自动化脚本。模型负责理解命令，工具负责执行动作，工作流负责把步骤串起来。这个模式看起来很直觉，也很好教。你可以把它做成教程，做成截图，做成一张“Agent 工作流大全”的图。
但苏煜这期访谈里反复指向的东西，比这个更深一层。工具调用（tool calling）只是让模型调用外部工具完成动作的能力。翻译成人话，它只是行动通道。一个人会按按钮，不代表他理解这份工作；一个 Agent 会调用工具，也不代表它理解工具所在的世界。
概念标注｜行动通道
工具调用解决的是“Agent 能不能做动作”；小世界解决的是“Agent 知不知道这个动作会造成什么后果”。前者是执行入口，后者才是可托付的基础。
早期 AutoGPT 的热潮就是一个例子。2023 年 3 月 30 日，游戏开发者托兰·布鲁斯·理查兹（Toran Bruce Richards）发布了开源项目 AutoGPT。它试图让 GPT-4 根据一个目标自动拆任务、调用工具、循环执行，像一个能自己推进工作的 Agent。
它的热度不是抽象的“爆火”。2023 年 4 月初，AutoGPT 很快成为 GitHub 热门项目；到 4 月 12 日，它已经有约 3 万 Star；到 4 月 16 日前后，Star 数又冲到 7 万多，一度超过 PyTorch 当时的 Star 数；几周后，它突破 10 万 Star。截至本文写作时的 2026 年 5 月，这个项目在 GitHub 上仍有约 18.4 万 Star。这个数字背后，是开发者社区在 2023 年春天非常真实的一次集体想象：如果模型能自己拆任务、自己调工具、自己往下走，那“自动干活的 AI”是不是马上就要来了？
但苏煜在访谈里提到 AutoGPT 时，指向的是另一面。AutoGPT 有过类似 Moment 的传播势能，却没有形成 ChatGPT Moment 那样的产业拐点。原因也在这里：它把语言模型包成一个 Agent 外壳，看起来什么都能做，最后能稳定做成的事情很少。
后来热度降下去，不是因为大家忽然不关心 Agent 了，而是因为真实使用很快暴露出硬问题：它容易陷入循环，容易被模型幻觉带偏，复杂任务拆解不稳，API 成本也高，还缺少足够好的人工校正和任务边界控制。

这不是偶然。
如果一个 Agent 只是会拆任务、会调工具、会继续执行，它很容易在真实任务里失控。因为真实任务不是一串动作，它背后有对象、流程、权限、例外、风险和评价标准。少了这些东西，它就像一个很会操作软件的新手。你看它鼠标动得很快，窗口切得也很熟，但你不敢把重要的事情交给它。
所以问题不是“它能不能做动作”。问题是：它懂不懂动作所在的世界。
苏煜讲**世界模型（world model）**的时候，用了一个特别好的例子：实习生进入公司。
一个刚毕业的新人进公司，不是学会几个软件按钮就可以开始独立负责项目。他要学组织结构，学谁说了算，学哪些审批是真的审批、哪些只是流程痕迹；他要学公司的工具链，学文档写给谁看，学同事之间哪些话能明说、哪些话只能从语气里听出来。
这些东西很少写在产品说明书里。它们也不完全在岗位描述里。你只有在里面待过、犯过错、被提醒过、看过别人怎么处理例外，才会慢慢知道。
这就是一个小世界。
**小世界（micro world）**不是玄学。它可以是一个公司，一个岗位，一个软件系统，一个行业场景，也可以是一个非常具体的工作流程。它里面有自己的对象、边界、权限、习惯、暗号、禁区和评价标准。
从实习生到专家，本质上就是学会这个小世界。用苏煜的语言说，就是构建一个专门化的世界模型。专家不是更会按按钮，而是知道什么时候不能按，按了以后谁会受影响，出了错以后先救哪一块。
从新手到可托付，中间差的不是按钮，而是小世界。
会操作工具的新手：知道怎么点、怎么调、怎么执行。
进入具体小世界：开始理解对象、流程、权限和例外。
形成专门化世界模型：知道每个动作背后的后果。
从能演示变成可托付：不只是能做，而是知道什么时候不能做。
这也解释了很多人使用 Agent 时的尴尬体感。
苏煜在访谈里提到，现在很多 Agent 第一次用起来很强，可能 60%-70% 的任务都能做对，但剩下 30%-40% 会莫名其妙地失败。这里不是在报一个外部基准测试（benchmark），而是在抓一种很真实的使用体感：它刚好卡在一个让人不舒服的位置。
如果它只有 10% 能做对，你不会有期待；如果它 99% 能做对，你会把工作交给它。最麻烦的是 60%-70%。它聪明到让你产生期待，又不稳定到让你不敢真正托付。
人类专家不是这样。一个老会计不会突然忘记哪些票据不能入账；一个老法务不会突然把“可谈判条款”和“底线条款”混在一起；一个熟悉你公司发布流程的人，也不会在最后一步忘记谁必须看一眼。
专家的可靠性，不是来自每次重新思考一遍所有规则，而是大量经验已经被压缩进身体里。到了某个节点，他不需要重新推理，就知道这里不能过。
Agent 现在缺的，就是这种压缩。
所以“很多工作不就是调用工具吗”这个反驳，只说对了一半。是的，工作表面上经常就是调用工具：打开表格、改字段、发邮件、提交代码、点一个按钮。但人类专家做同样的动作时，脑子里带着后果模型。他知道这个字段改了以后哪个系统会同步，邮件抄送少了谁会出问题，代码合并前哪个测试必须跑，按钮按下去之后谁会被影响。
工具动作一样，世界理解不一样。
提示词和工具教程解决不了全部问题。你当然可以把命令写得更清楚，但如果 Agent 没学会你的小世界，它还是会在 30%-40% 的地方摔跤，而且经常摔在你最不希望它摔的地方。
回到 OpenClaw。
OpenClaw 的历史位置，不是“它发明了 Agent”。苏煜对它的理解更接近 ChatGPT Moment。ChatGPT 也不是从零发明了语言模型，在它之前，语言模型已经走了很多年。ChatGPT 做成的，是把底层能力用一个足够简单、足够开放、足够可感知的方式推到大众面前。
OpenClaw 也是类似的东西。
按照苏煜的拆法，它的新意不在某一段代码，而在四件事同时到位：底层能力已经准备好，交互方式变得更低门槛，权限和作用范围被放大，开源发布又让大规模试用和模仿变得容易。

在 OpenClaw 之前，工具使用、代码 Agent、电脑使用型 Agent、任务拆解这些能力都已经存在。很多研究者看代码，可能会觉得“这里没有什么全新的算法”。但 Moment 的意义不总是算法新。有时候，是交互方式、权限范围和发布策略一起到位，让已有能力突然变得可见。
OpenClaw 的新意，正在这里。它不只是让 Agent 多接了一个工具，而是给了 Agent 更大的行动范围。它能接触文件、进入软件环境、持续执行任务，也更接近一个真实工作流。
电脑使用型 Agent 和代码 Agent 的关键也在这里。它们不是简单的功能分类，而是 Agent 进入数字世界的入口。我们每天的工作不在抽象的 API 里，而在浏览器、文档、表格、图形界面（GUI）、集成开发环境（IDE）和各种已经被公司流程改造过的软件里。
“未来所有东西都会变成应用接口（API），Agent 只要调接口就好”，这个想法太干净了。现实世界不会为了机器变干净。图形界面里沉淀了大量业务逻辑，很多按钮、弹窗、灰色选项、审批流，都是过去多年人类组织和软件系统互相妥协后的痕迹。
Agent 要接手这种任务，就必须学这些痕迹。
OpenClaw 给人的冲击在这里。Agent 不再只是“回答问题的 AI”。它开始进入人类已经构造出来的数字世界。这个世界不是为机器准备的，它里面充满人的习惯、组织的层级、软件的历史包袱和一堆不能写进教程的例外。
一旦 Agent 能进入这个空间，软件的价值就会变。
过去的软件即服务（SaaS）卖的是工具。用户买一个系统，学会怎么用，然后自己负责把结果做出来。CRM 是工具，表格是工具，项目管理系统也是工具。它们提供按钮、字段、视图、流程，但最后的劳动仍然在人身上。
Agent 化的软件，开始往另一边走。用户要的不再只是工具，而是结果。你不是想买一个更好的按钮，你是想让某件事被完成。
这就是“软件从工具走向劳动交付”的意思。以前你买的是一套系统，自己进去点按钮；以后你买的可能是一件事被做完，比如线索被筛过、合同被初审过、代码被改到可以合并。

这个变化会让人兴奋，也会让人焦虑。兴奋在于，很多过去只有大公司、大团队、大预算才能完成的事情，可能会被更小的团队做出来。焦虑在于，如果软件开始交付劳动，知识工作的很多部分都会被重新定价。
苏煜在访谈里说得很直：短期真正值得担心的，不是 AI 已经有了自我意志，也不是科幻式的存在性风险，而是工作替代（job displacement）。
这个判断很现实。因为 Agent 如果真的能大规模替代知识工作，而社会又没有足够的新岗位、足够好的收益分配机制，收益最后集中到少数头部公司和资本手里，那影响会非常大。
这不是一句“大家拥抱 AI”就能糊弄过去的。
但它也不等于普通人只能坐在原地等着被替代。苏煜后面给出的方向，是让更多人获得前沿 Agent 能力。不是只让少数巨头把 Agent 做成替代人的机器，而是让每个有独特想法、独特洞察的人，也能把自己的洞察变成可以产生价值的 Agent。
这个方向听起来很大，落到本文里，其实就是一句很具体的话：模型公司不会通吃所有小世界。
世界不是一个世界。它由很多小世界组成。每个行业、每家公司、每个岗位、每套软件、每群用户，都有自己的流程、约束和例外。通用模型可以给你一个很强的起点，但能产生稳定价值的，经常是那些专门化之后的 Agent。
差异会落在很具体的东西上：你的工作流有没有被表达出来，你的领域记忆有没有沉淀下来，真实部署之后有没有反馈，结果是不是有专家能评估。
说白了，未来的竞争不只是“谁的模型更大”。它还会变成：谁更懂一个小世界，谁能把这个小世界教给 Agent。
为什么提示词和工具视角会这么流行？
因为它好教、好卖、好截图。一个提示词模板可以直接复制，一个工具调用流程可以画成图，一个 Agent 工作流可以做成教程。它们都很适合传播。
难教的是世界模型：这个工作里有哪些对象，流程真实怎么走，谁有权限，什么情况算例外，结果由谁评价，失败以后先救哪里。
这些东西很难变成一张漂亮的图，因为它们不是干净的。它们更像你电脑里那个用了很多年的工作目录：有些文件夹名字很清楚，有些名字是三年前随手取的；有些文档应该删但一直没删；有些规则没人写下来，但每个人都知道不要碰。
这才是真实工作。

通用模型会变强，但百万个具体小世界不会自动变干净、变标准、变成 API。
所以以后你让 Agent 做事，第一件事可能不是写提示词，而是写一份工作世界说明书。至少要写清楚八件事：
项目
你要说清楚的问题
对象
这个工作世界里有哪些实体、文件、角色、系统、状态？
流程
一件事从开始到完成，真实路径是什么？
权限
谁能决定？谁能审批？哪些动作不能随便做？
例外
哪些情况不能套标准流程？
评价标准
什么叫做“做对了”？谁说了算？
失败案例
过去常见错误是什么？错了会造成什么后果？
风险边界
哪些任务必须人审？哪些信息不能交给 Agent？
反馈信号
Agent 做完以后，靠什么持续校正和学习？
如果你在用 Agent，这张清单比多背十个提示词更重要。提示词是命令，小世界说明书是上下文。没有上下文，命令越漂亮，越像在一间陌生办公室里大声喊话。
如果你在做产品，不要只想着给软件加一个聊天框。聊天框很容易加，但能留下来的东西，是工作流、领域记忆和评价闭环。说得再直一点，就是它要记得这个行业过去怎么做、这家公司怎么判对错、用户改过哪些结果。Agent 要想从演示变成生产力，必须在一个具体小世界里越用越熟。
如果你在做公司，也不要只问“模型公司会不会把我吃掉”。更应该问：你的业务里有没有足够复杂、足够具体、足够难被通用模型一次性覆盖的小世界？这些小世界有没有数据、反馈和专家评价，可以让 Agent 从实习生变成老师傅？
更具体地说，可以用一个条件式框架来判断：
如果一项工作只有清晰步骤、低风险、少例外，那你需要的可能只是自动化脚本或普通工作流。
需要调用工具，但失败后果不大时，可以让 Agent 先做执行者，人类负责抽查和收尾。
碰到复杂权限、隐性规则、例外处理和结果责任，就不要先问“提示词怎么写”，先写小世界说明书。
已经能沉淀数据、反馈和专家评价的工作，才值得继续训练成专门化 Agent。
这才是工作替代焦虑里比较有用的那一部分。
焦虑本身没有问题。问题是焦虑如果只停在“我会不会被替代”，它就没有出口。你可以换一个问题问自己：
我能不能把自己的小世界，变成 Agent 可以学习的东西？
OpenClaw Moment → 工具调用误解 → 小世界 → 世界模型 → 劳动交付 → 小世界说明书
这条线索对应的不是“多学一个工具”，而是把自己的工作世界变成 Agent 可以学习、执行和被校正的结构。
这不是一个轻松的问题。很多人会发现，自己每天做了很多事，但很少把对象、流程、例外、权限和评价标准说清楚。我们靠经验在跑，靠感觉在判断，靠“你来了就知道了”在传递知识。
过去这也许够用。因为人会慢慢混熟。一个新人进来，坐在旁边看两个月，很多东西就懂了。
但 Agent 不会自动混熟。你不把小世界表达出来，它就只能在表层动作里打转。它会显得聪明，会给你一个像样的答案，会把鼠标移动到正确的位置附近，然后在某个你没说清楚的例外上摔一跤。
OpenClaw Moment 让我们看到，Agent 开始接触真实任务。苏煜这期访谈把这件事继续往下推了一层：接触任务以后，Agent 要学的不是更多按钮，而是一个世界。所以未来会用 Agent 的人，不一定是最会写提示词的人，是最能把自己的工作世界说清楚的人。
本文关于苏煜观点的主要理解，来自张小珺《商业访谈录》EP139《Agent的综述：和苏煜聊Agent技术史、OpenClaw Moment、边界的消弭和社会的辐射》。感谢张小珺做了这场深度对话，把 Agent 技术史、OpenClaw Moment、世界模型和社会影响这些原本容易散掉的话题，放进了一个可以被普通读者理解的叙事里。
